# Pod 运行时标签变更导致亲和性错误

## 场景

云组迁移方案中，为了在不停机的情况下将 DB 实例从一个云组迁移到另一个云组，运维同学通过直接修改运行时 Pod 的标签来改变其所属分组。但当 kubelet 重启触发 Pod 重建时，该 Pod 因为标签已变更（属于新分组）但容器配置仍然是旧分组的配置，处于「中间态」，重建时产生亲和性错误，容器无法创建成功。

## 问题本质

- **Pod 标签修改是运行时操作**，不触发 Pod 重建或配置更新
- **中间态**：Pod 标签归属新分组，但实例未升级（关键点），实际调度时亲和性规则对新标签不匹配
- **触发条件**：kubelet 重启 → 发现 Pod 需要重建 → 使用新标签进行调度 → 亲和性约束不满足 → 容器创建失败 (Pending)

## 教训

1. **迁移方案必须覆盖故障场景**：只测试了正常迁移流程，未测试 kubelet 重启等「带病运行」场景
2. **中间态是最危险的**：跨分组迁移后未完成升级前，系统处于不一致状态，任何 node 抖动都会触发重建失败
3. **扫描+升级策略**：迁移后应扫描所有实例检查状态，尽快完成升级消除中间态
